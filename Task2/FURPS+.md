| Код | Требования | Комментарий |
|-----|------------|-------------|
| F | Функциональные (Functionality) | |
| | На сайте клиент видит список депозитов с актуальными ставками. Заявка (телефон, ФИО) попадает в систему кол-центра. Менеджер звонит и может предложить особые условия. Новый клиент после звонка проходит идентификацию только в отделении. | |
| | В интернет-банке клиент видит актуальные и персональные ставки, указывает счёт и сумму и подтверждает заявку СМС-кодом. | |
| | Ставки депозитов сейчас только в Excel. С ними работают бэк-офис депозитов и бэк-офис кредитов. Возможно, эти ставки и текущий процесс согласования ставки по заявке стоит реализовать в АБС. Клиент получает СМС после подтверждения ставки и после открытия депозита. | |
| | На сайте кредит показывается по условиям из кредитного конвейера. Заявка: телефон и ФИО. Если указан паспорт, решение сразу через скоринг и только общие данные бюро, потому что клиент новый. Затем СМС о визите в отделение. | |
| | В отделении менеджер подаёт заявку через АБС. Если одобрение уже получено на сайте, он продолжает ту же заявку. Новую создаёт для полностью нового клиента. | |
| | В интернет-банке витрина кредитов как на сайте плюс предодобренное предложение. Клиент указывает счёт зачисления и данные для подачи заявки и подтверждает её СМС-кодом. После подачи, если ситуация изменилась, скоринг повторяется по упрощённой процедуре. Клиент получает СМС при смене статуса заявки. | |
| | Заявки по предодобренным предложениям сотрудники обрабатывают в тот же рабочий день. | |
| U | Удобство использования (Usability) | |
| | Интерфейс работы удобный для клиента. | |
| | Цвета и элементы интерфейса берутся из дизайн-системы банка. | |
| R | Надёжность (Reliability) | |
| | Сервисы работают 24/7 и доступны в 99,9% случаев, в том числе интернет-банк при сбое основного ЦОД и при требуемой нагрузке. Сейчас интернет-банк стоит в одном ЦОД на одной группе серверов, и его команда считает это требование пока невыполнимым. Резервный ЦОД у банка есть, на него можно переключиться. | |
| | Нужно равномерное горизонтальное масштабирование и распределение запросов между серверами, приложениями и ЦОД. АБС из-за базы масштабируется только вертикально. | |
| | Онлайн-заявки не должны ставить под угрозу АБС: база уже перегружена. Прямой работы интернет-банка с API АБС в новом процессе лучше избежать. | |
| | Кредитный конвейер и скоринг рассчитаны на рост нагрузки, работают 24/7 и масштабируются горизонтально. Скоринг в рабочие часы не нагружать предрасчётами. | |
| P | Производительность (Performance) | |
| | Отклик по всем операциям должен быть в миллисекундах. | |
| | Справочные данные, которые при платежах загружаются дольше секунды, нужно отдавать быстрее. | |
| S | Поддерживаемость (Supportability) | |
| | Доработки на технологиях, которые уже есть в банке, например MS SQL и Oracle. Новую технологию можно взять, если она совместима с текущими платформами и в банке уже есть экспертиза хотя бы на уровне языка. | |
| | Если нужны очереди, лучше Kafka. Текущая версия платформы интернет-банка с ней несовместима. | |
| | Перевод интернет-банка на микросервисы только в рамках открытия депозитов. Для дальнейшего расширения нужна документация. | |
| | СМС-функционал ядра дорабатывает команда банка, без доработки подрядчика. | |
| +R | + Ограничения (Restrictions) | |
| | В объёме только MVP. Заявку на депозит обрабатывает менеджер бэк-офиса и подтверждает условия в АБС. | |
| | Чувствительные данные с сайта и данные интернет-банка при передаче защищаются шифрованием трафика. | |
| | Обмен между базами АБС и кредитного конвейера нельзя ускорить и нельзя проводить чаще раза в сутки. | |
